The numbers

What happens if each store gets its own size mix?

A clothing brand with 40 stores sends every store the same mix of sizes, but customers in Tokyo buy smaller sizes than customers in Chicago. If each store gets its own size mix instead, it misses fewer sales, and no store's stock target goes up. A stock target is the number of items a store should have right after a delivery, and a style is one design, such as a black T-shirt.

      Who benefits

      Who gains, and why does it work?

      Why does one size mix fail?

      A style is one design, such as a black crew-neck T-shirt, and each store sells 60 styles in six sizes, from XS to XXL. Every Monday, the head of planning sets each store's stock target for every style and size. Today, every store's target uses the same size mix, for example 34% size M and 16% size S.

      Tokyo store

      Customers buy more S than the mix sends, so size S sells out soon after each delivery and those sales are lost.

      Chicago store

      Customers buy more L and XL, so those sell out while the extra S items sit unsold until the end-of-season sale.

      Who is better off, and how?

      Head of planning

      A short list of size changes to make each Monday, instead of one mix for every store.

      Store teams

      Fewer customers told "we don't have your size", and less unsold stock to move at the end of the season.

      Supply chain

      A way to test how often to deliver, and how much safety stock to send, before changing the delivery schedule. Safety stock means extra items sent in case customers want more than forecast.

      Finance

      An estimate of extra profit, which they can compare with the cost of the extra deliveries before approving the change.

      How do we know what each store needs?

      Use each store's own size pattern

      First, forecast how many items of each style a store will sell. Then split that number by the store's own size pattern, learned from last season's sales across all its styles.

      Option I did not choose: a forecast for every single size

      A single style in a single size sells only a few items a week. Forecasts that small are mostly guesswork, so I forecast per style and then split by size.

      The mistake to avoid: "sold out" is not "nobody wanted it"

      When a size sells out, its sales drop to zero, and if you treat that zero as "no demand", the size looks unpopular. Then you send even fewer next time, so the problem gets worse every season.

      The fix measures how fast each size sold while it was on the shelf. If a size was never sent at all, it borrows that store's pattern from its other sizes.

      Why can you trust these numbers?

      A planner will only act on numbers they trust, so this demo gives each number one meaning and checks its own answers.

      Missed sales
      Items customers wanted in weeks when their size had run out.
      Sold, out of delivered
      Items sold divided by items delivered to the store, where a higher number means a smaller share of the stock was left unsold.
      Left over at the end
      Items still in the store when the season ends, which may need to be sold at a discount.

      Five questions with known answers

      Questions 1 to 4 are counted straight from the raw made-up data each time the page loads. Question 5 checks that the plan at the starting settings still gives the expected total, and any changed answer needs investigating.

        What does this demo not show yet?

        • All data is made up, so the results show how the method works, not what a real brand would gain.
        • In this demo, stores can always be topped up, but a real warehouse can run short of some sizes.
        • The sold-out fix is an estimate: for example, it assumes a size that sold out in a week was on the shelf for half that week.
        • The profit figure leaves out the cost of the extra deliveries.

        How I built it

        Behind Sizes That Sell

        1. 01 · The idea

          Based on real fashion retail work

          From January to September 2026, I worked part-time as a Business Analyst (Data & Performance) at LSOUL, a fashion brand. I combined 9+ data sources from three markets (Vietnam, Thailand and China) into one data hub. I also ran daily, weekly and monthly business performance reports for leadership, which flagged weak sales channels and stockout risks.

          This demo explores a question that kind of reporting raises: when sizes keep running out, how should stock be split between stores? It is not a copy of any LSOUL project. No LSOUL data, screens or code are used, and every store, style and number here is made up.

        2. 02 · The plan

          A consulting plan before any code

          The proposal used a consulting method: start with the answer and the person who decides, then work through six steps. Each step answers one plain question.

          The six planning steps
          StepThe questionIn this demo
          1 · GoalWho decides what, and when?The head of planning sets stock targets by size each Monday.
          2 · MeaningWhat does each number mean?Missed sales, sold out of delivered, and leftover stock, each defined once.
          3 · DataWhat does one row describe?One store, style and size for one week, with sales and stock.
          4 · BuildWhat is the simplest method that works?Forecast per style and store, then split by the store's size pattern.
          5 · CheckHow do we know it is right?Test on a season the method never saw, against today's plan, plus five questions with known answers.
          6 · OperateWho runs it after I leave?A weekly refresh, an alert for late data, and a one-page guide (planned, not built).

          The plan also named one hard decision (per style, not per size) and one trap (sold out is not no demand). Both appear in the "Who benefits" tab.

        3. 03 · The data

          Made-up data that behaves like a real brand

          The browser creates the data from a fixed starting number, so every visit shows the same results. There are 40 stores in 12 cities, and cities lean towards smaller or larger sizes. Each store sells 60 styles over two 26-week seasons: one season to learn from and one to test on.

          In the first season, every store got the same size mix, just like the brand's current plan. That creates realistic sell-outs for the method to learn from. A real version would add the steps this demo skips: collecting daily store files, cleaning them, and storing one row per store, style and size each day.

        4. 04 · The build

          Built with Claude Code

          I chose the idea, set the direction and asked for each change. Claude Code, running Anthropic's Claude Opus 5.5, wrote the page in plain HTML and JavaScript, with no libraries and no server. The work went through five stages: plan, build, verify, review and ship.

          A self-check file runs automatic checks on the logic, for example that both plans use the same stock targets. To prove the tests work, Claude Code also broke the logic on purpose and confirmed that the tests failed.

        5. 05 · The review

          Checked by a second AI

          OpenAI's GPT-6-Astra, used through Codex with medium reasoning, reviewed the page without editing it. It scored each version against a 100-point checklist covering plain language, honesty, layout, accessibility and privacy, and Claude Code fixed every finding before the next round.

          In this project, the separate reviewer caught overclaims, unclear labels and a chart that was hard to read on phones. The scores for each round are below.

        6. 06 · The stack

          Simple on purpose

          The page is three small files hosted on Cloudflare Pages and published from GitHub, the site where the code is stored. There is no server, no cookies and no tracking. Your browser only remembers whether you have already seen the tour.

        7. 07 · Next

          What I would do with real data

          • Use the brand's real daily sales and stock counts instead of made-up data.
          • Refresh the numbers every week before the Monday meeting, with an alert if a store's data is late.
          • Use the real profit per item from finance instead of an assumed one.
          • For new stores with no history, borrow the size pattern of similar stores.
          • Write a one-page guide, so the planning team can run it without me.
